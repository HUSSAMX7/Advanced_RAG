# إعداد الدخول بالإيميل — الفيتشر الأولى

الكود جاهز للتجربة المحلية. يلزم مشروع Supabase لاختبار الإيميل الحقيقي؛
لا توجد خدمات خارجية مجهّزة حتى الآن، ولم يُشترَ دومين أو اشتراك.

## أول خطوة: مشروع Supabase

1. افتح [إنشاء مشروع](https://supabase.com/dashboard/new) من حسابك.
2. استخدم منظمة على خطة Free للمراجعة الأولية، واسمًا مثل `advanced-rag-dev`.
   أدخل كلمة مرور قاعدة البيانات بنفسك واحفظها؛ التطبيق لا يحتاجها في هذه الفيتشر.
3. اختر منطقة مناسبة من المناطق المعروضة وانتظر جاهزية المشروع.
4. من Connect أو إعدادات API، خذ **Project URL** و**Publishable key**
   الذي يبدأ بـ`sb_publishable_`. هذان قيمتان عامتان، ولا تحتاج إرسال مفتاح
   Secret أو service-role أو كلمة مرور قاعدة البيانات.
5. من جذر المشروع شغّل الأمر التالي بالقيم العامة الفعلية:

   ```powershell
   uv run python scripts/configure_identity.py --supabase-url "https://YOUR_PROJECT.supabase.co" --publishable-key "sb_publishable_YOUR_KEY"
   ```

   الأداة تحفظ القيم في `.env` وتحتفظ بمفتاح التشفير الموجود. تم تجهيز مفتاح
   التشفير محليًا بالفعل، ولا يُعرض أو يدخل Git.

6. في إعدادات Auth، أبقِ تسجيل الدخول بالإيميل مفعّلًا. اضبط Site URL وRedirect
   URLs على `http://127.0.0.1:8001/` للمراجعة المحلية. رسالة Magic Link الافتراضية
   مناسبة لطريقة الدخول المختارة؛ لا تحولها إلى رسالة رمز رقمي.
7. ابنِ الواجهة وشغّل الخادم، وافتح الصفحة وأرسل رسالة تحقق. افتح رابطها على
   نفس الجهاز وفي نفس المتصفح الذي طلبها حتى تتوفر حالة PKCE المحلية.

   ```powershell
   npm --prefix frontend run build
   uv run advanced-rag-web
   ```

## التجربة الأولى وإرسال البريد للمستخدمين

خدمة Supabase الافتراضية ترسل فقط لعناوين فريق المشروع، لذلك يمكن بدء مراجعة
الدخول بإيميل حسابك/عضو الفريق. هذه تجربة محدودة، ولا تحقق شرط الدخول العام
بأي إيميل. قبل اعتبار إرسال التحقق جاهزًا للمستخدمين، نحتاج إعداد Custom SMTP
واختبار وصول الرسائل إلى عناوين خارج فريق المشروع.

لإرسال مستقر باسم المشروع، اختر دومينًا نملكه ومزوّد بريد، ثم اضبط سجلات التحقق
التي يعطيها المزوّد واربط SMTP في Supabase. اختيار المزوّد والدومين والتكلفة
لم يُعتمد بعد؛ لا ننفّذ شراء تلقائيًا.

Brevo خيار يمكن تقييمه للتجربة: توثيقه يصف استبدال عنوان المرسل غير الموثّق
مؤقتًا بعنوان تحت `brevosend.com`، بما فيه العناوين المجانية. توثيق SMTP يوصي
بتوثيق الدومين أولًا، لذلك نتحقق من شروط تفعيل الحساب والإرسال قبل الاعتماد على
هذا الخيار بدون دومين، ولا نضمن أنه يتجاوز متطلبات المزوّد.

## ما نراجعه قبل الفيتشر التالية

- وصول رابط التحقق الحقيقي ودخول الحساب وخروجه.
- حسابان لا يريان بيانات أو مفاتيح بعضهما.
- تحديث الضيف يحتفظ بشغله، وإغلاق الصفحة ثم فتحها يبدأ من جديد.
- تنبيه 15 دقيقة، مهلة دقيقة، التجديد، والإلغاء والتنظيف عند الانتهاء.
- مفتاح OpenAI المفقود وخدمة PDF المختارة يعرضان خطأ يطلب المفتاح الصحيح.

لا نبدأ الفيتشر التالية قبل مراجعتك وموافقتك. إعداد SMTP العام واختباره يظل
ضمن أعمال إكمال هذه الفيتشر إذا كان مطلوبًا قبل اعتمادها.
